# :core-primehack — how PrimeHack is embedded

PrimeHack (github.com/shiiion/dolphin, GPL-2.0-or-later like Dolphin) is built from **`/Users/ry/Desktop/claude/primehack-romcore-src`**,
an APFS clone of `primehack-src` (`cp -cR`, free) on branch `romcore`. `primehack-src` itself is untouched, so the old
`romrunner-builtinemulators` build still works. The clone's `origin` is still shiiion/dolphin: **never push it**
(`remote.origin.pushurl` is set to a dummy).

Recreate the clone from scratch:

    cp -cR primehack-src primehack-romcore-src
    python3 romcore/core-primehack/tools/relocate_primehack.py primehack-romcore-src   # mechanical renames (below)
    cd primehack-romcore-src && git checkout -b romcore && git add -A && git commit -m relocate   # relocation commit
    git am ../romcore/core-primehack/patches/000*.patch
    git -C Externals/libadrenotools am ../../../romcore/core-primehack/patches/libadrenotools/*.patch   # primehack_* hook lib names

(`patches/` = `git format-patch` of the clone's `romcore` commits on top of the relocation commit.)

## Making two Dolphin-derived engines coexist in one APK (agreed recipe for :core-dolphin too)

| Collision | Fix used here | What :core-dolphin must use instead |
|---|---|---|
| JNI library name `libmain.so` | CMake target `main` -> **`primehack_main`** (`System.loadLibrary("primehack_main")`) | e.g. `dolphin_main` |
| JNI Java package `org.dolphinemu.dolphinemu` (hard-coded in `Java_org_dolphinemu_dolphinemu_*` symbols and `FindClass("org/dolphinemu/...")` strings in jni/ and Source/Core) | sed over Kotlin/Java/XML/C++: -> **`com.noryan.romcore.core.primehack.jni`**; library `namespace` follows | e.g. `com.noryan.romcore.core.dolphin.jni` |
| Android resources merge by NAME across modules (layouts, menus, drawables, xml, anim, font) — same name in both engines silently overrides | every file resource renamed `*_ph`, ViewBinding classes `XxxPhBinding`, `R.layout.x` refs | pick another suffix |
| Theme/style names | all 28 styles prefixed `PH` (`PHTheme.Dolphin.Main`) | another prefix |
| Manifest components with fixed authorities (`${applicationId}.filesprovider`, `.user`), launcher activities, `DolphinApplication` | library manifest stripped to features/permissions; only `PrimeHackActivity` (declared in :core-primehack) exists | same |
| Gradle coordinates `org.dolphinemu:app` (composite-build substitution) | clone's `group = "romcore.primehack"` -> `romcore.primehack:app` | use a different group |
| Hook libs `libhook_impl.so`, `libmain_hook.so`, `libgsl_alloc_hook.so`, `libfile_redirect_hook.so` (Externals/libadrenotools, same names in any Dolphin build -> duplicate-.so merge error) | targets + dlopen strings prefixed `primehack_` (patch in `patches/libadrenotools`) | prefix `dolphin_` |
| Old pre-AndroidX support libs via `com.nononsenseapps:filepicker` (duplicate classes; host has no Jetifier) and core-library desugaring | excluded / disabled (minSdk 30) | same |
| Process / globals | `PrimeHackActivity` is `android:process=":primehack"`; process is killed when the game ends | `:dolphin` |
| User data (Config, GC/Wii saves, Sys, drivers, cache, prefs key `sysDirectoryVersion`) both default to `getExternalFilesDir/Sys` etc. | `DirectoryInitialization` patched: everything under a `primehack/` subfolder (`<externalFiles>/primehack`, `<files>/primehack/{Sys,GPUDrivers}`, key `primehack.sysDirectoryVersion`) | `dolphin/` subfolder |

`relocate_primehack.py` does the first four rows; the rest are the committed patches. A decompiler was not needed anywhere:
everything is built from source.

## Input path

    Physical pad -> InputRouter (device auto-profile + user mapping + hotkeys) -> PrimeHackSession.injectButton/injectAxis
      -> RomCoreInput (JNI) -> virtual ciface device "RomCore/0/RomCore Pad"  (added in ControllerInterface/Android/Android.cpp)
      -> GCPad1 / Wiimote1 expressions generated by PrimeHackProfiles (incl. PrimeHack "Camera Control" = right stick + gyro)

The profile is generated at every launch (PrimeHackConfig), so it never depends on which handheld is connected.
Dolphin's own `ControllerInterface.dispatchKeyEvent` is bypassed for physical events.

## Defaults

* Wii (Prime 3 / Trilogy): A fire (A or R2), B jump (B or L1), Y = morph ball (Nunchuk C), L2 = lock on (Nunchuk Z), left stick move,
  right stick + gyro camera, D-pad visors, X + D-pad beams, X = spring ball/grapple, START/SELECT = 1/2.
* GC (Prime 1/2): face buttons 1:1, Z = R1, L/R = L2/R2, D-pad visors, L1 + D-pad beams (C-stick), right stick + gyro camera.
* Other GC games: standard layout, right stick = C-stick.
* Gyro aim on by default for Prime titles (`PrimeHackPrefs`, SharedPreferences `romcore_primehack`: gyro_aim, gyro_scale, gyro_invert_x/y).

## Menu / session

`RomCoreMenu.attach` hosts the shared menu; Back/HOME/hotkeys toggle it (Dolphin's pop-out menu is replaced via the patched
`protected open fun toggleMenu()`). Save/Load State use `NativeLibrary.SaveStateAs/LoadStateAs` into
`<filesDir>/states/primehack/<romHash>/slotN` (the CoreSessionBase convention).

## Packaging note for :app

`libprimehack_main.so` is arm64 only. If the Adreno custom-driver feature of Dolphin is ever wanted, the app needs
`packaging.jniLibs.useLegacyPackaging = true` (not needed for the default system driver).

## GPU memory / shader mode (do not change without measuring)

`GFX.ini ShaderCompilationMode` must stay `0` (specialized shaders). Ubershader modes (1/2) make the Adreno Vulkan driver
allocate ~24 MB of private GPU scratch memory per pipeline (kgsl `VK/others(58)`; not counted in PSS): hybrid mode 2 reached
~4 GB in Prime 1's first room and +0.9 GB at the first morph-ball press, which got the process killed by lmkd on the Thor.
`PrimeHackConfig.applyEarly` writes the key before the native engine loads GFX.ini (stale values would otherwise be live for
one more launch). Measure with: `adb shell cat /sys/kernel/debug/kgsl/proc/<pid>/mem` (sum of sizes) or logcat tag `RomCoreMem`.

## Shader cache persistence (mode 0 stays; measured numbers in the perf notes of the commit)

* Dolphin writes three things per game/backend: `Cache/Shaders/<api>-<type>[-<gameid>]...cache` (shader + pipeline-UID caches,
  append-only `LinearDiskCache`/UID file) and the Vulkan driver blob `Vulkan-Pipeline-<hostconfig>.cache` (VkPipelineCache).
  `WaitForShadersBeforeStarting=True` replays every recorded UID (`CompileMissingPipelines`) behind the RomCore loading bar
  ("Compiling shaders x/total"), so cached games start warm.
* Location: `<externalFiles>/primehack/Cache/Shaders` (= `/sdcard/Android/data/com.noryan.romcore/files/primehack/Cache/Shaders`).
  Previously it was `externalCacheDir/primehack`, which the system / "Clear cache" may wipe; `DirectoryInitialization` now uses the
  user dir and moves an old `Shaders` dir over once.
* Dolphin only fflush()es the append-only caches and saves the Vulkan blob on a *clean* backend shutdown. RomCore kills the
  process when the game ends, so `NativeLibrary.FlushShaderCaches(full)` (new JNI; runs as a GPU-thread `AsyncRequests` event)
  is called by `ShaderCacheKeeper` on menu open (pause), `onPause`, and every 60 s (cheap fflush only).
* `NativeLibrary.GetShaderCacheEntries()` = entries restored from disk this run; logcat tags `RomCoreShader` / `RomCoreUi`.
* Never bundle game-derived caches in the repo/APK (commercial-game derived, GPU/driver specific): they are built locally.

## Super Mario Sunshine 60 fps + widescreen on this core (and the Sys-extraction bug that blocked it)
`PrimeHackConfig.apply` enables `$60FPS` and `$Widescreen` via `SunshineFps` (same logic as :core-dolphin: EnableCheats + bare code
names in `[Gecko_Enabled]`; Dolphin strips the `[creator]` suffix from code names). Root cause of "60 fps never unlocked on PrimeHack":
`DirectoryInitialization.extractSysDirectory` used a non-recursive `mkdir()` for `<files>/primehack/Sys`; on a fresh install
`<files>/primehack` did not exist yet, so NOTHING was extracted (no `GameSettings/*.ini`, so the Gecko code bodies did not exist),
and the revision was stored anyway so it was never retried. Fixed in primehack-romcore-src (`mkdirs()` + re-extract when
`Sys/GameSettings` is missing; patch 0008), which also restores every other Sys default (per-game INIs, GraphicMods) for the Prime games.
